# A/C 完整训练验证的必要性与后续安排

日期：2026-10-21。

**当前 20k 续训用于判断已训练模型能否从 A/C 中受益；若要声称 A/C 改善完整训练过程，还需要从统一初始化开始的 300k 公平比较。** 5k 筛选已完成。更新至15:46:49北京时间：六组20k训练均达到预算，但最终逐步输入/目标哈希配对验收未通过，尚未得到有效的确认阶段结论。本文提出的300k实验尚未启动，以下安排是建议，不是已完成结果。

本轮各组的定义是：C0 为前轮 B0、seed 0 的 300k 最终检查点；B0 是从该 C0 开始、重新建立优化器的 L1 续训对照；A/B1 仅引入深层相关 PFA；C/B3 保留原始独立 PFA，增加平滑结构损失。它们不同于前轮 RGB 校准模块的 G1/G2/G3 实验。当前配置见 [方案 A 服务器配置](../configs/plan_a_server.yaml) 和 [方案 C 服务器配置](../configs/plan_c_server.yaml)。

**5k 筛选已经说明什么**

筛选使用 CBSD68 固定的 20 张开发图、一个训练种子 100，以及三个固定的评测噪声种子。Gaussian15 单独作为 ID 报告；其余六个条件形成本轮 OOD 指标。下表为这一相同评测协议下的结果，不能直接与前轮不同条件集合的 OOD 总分混用。

| 模型 | OOD PSNR（dB） | 相对匹配续训 B0（dB） | 相对原始 C0（dB） |
|---|---:|---:|---:|
| C0：原始 300k 检查点 | 28.7232 | — | 0 |
| B0：仅 L1 续训 | 28.6382 | 0 | −0.0850 |
| A/B1：相关 PFA | 28.6216 | −0.0166 | −0.1016 |
| C/B3：结构损失 | 28.6440 | +0.0058 | −0.0792 |

以上数值保留四位小数。A 和 C 均未达到预设的相对 B0 增加 0.1 dB 的工程门槛。C 的小幅相对增益也没有抵消共同续训相对于 C0 的下降，因此目前不能宣称它改善了最终模型。一个训练种子和 20 张开发图也不足以支持稳定性或统计显著性的结论。逐项结果及报告见 [5k 筛选结果目录](../results/ac_20261021/screen/)，指标定义及门槛见 [评测实现](../tools/evaluate_pfa.py) 和 [汇总实现](../tools/summarize_ac.py)。

**20k 续训与完整 300k 训练回答不同的问题**

本轮 20k 从已经完成 300k 训练的同一个 C0 出发，使用全新的 AdamW 和从 `1e-5` 降到 `1e-6` 的单周期余弦学习率。种子 101/102 改变续训中的数据顺序、输入噪声、Mixup 和 PFA 随机性。它们共用同一个初始去噪模型，因此检验的是“给定 C0 后的续训收益”，并不覆盖随机解码器初始化带来的差异。

A 改变训练期特征扰动，C 改变优化目标。两者从训练初期开始使用时，可能影响整个优化路径；在成熟 L1 模型附近进行低学习率适配，不能替代这种测试。因此，20k 的正结果不能直接证明完整训练有效，20k 的负结果也不能直接否定从初始阶段使用这些设计的效果。两类结论都需要限定在各自实际测试的协议内。

这里的“从统一初始化开始”指加载同一份 RN50 预训练编码器、重新随机初始化解码器，并从第 1 步训练去噪任务；不是把 CLIP 编码器也随机初始化。当前 [续训入口](../tools/run_pfa_experiment.py) 明确加载 C0，所以仅把预算数字改为 300k，仍然会成为另一种长续训实验，不能视为完整训练复验。

**为什么建议建立匹配的完整 B0**

前轮 [B0 完整配置](../final_results_20261021/runs/full/B0/seed0/effective_config.json) 使用 432 张训练图、Gaussian15、batch 16、FP32、AdamW 初始学习率 `3e-4`、原始 `92000/208000` 调度和 300k 步，没有加载完整去噪 C0。旧 B0 权重可以作为有效的历史参考。

新代码在 `rho=0` 且 `pfa_seed=None` 时仍调用原始 `torch.randn_like`，保留旧的随机行为；[PFA 实现](../basicsr/models/archs/spatial_pfa.py) 和 [兼容测试](../tests/test_spatial_pfa.py) 提供了对应证据。但当前 A/C 配置显式设置 `pfa_seed=seed+30000`，采用按层独立的随机流。即使 B0 的扰动仍服从相同的独立高斯分布，具体随机轨迹也不同于前轮 B0。

因此，为当前实现建立完整训练主表时，建议三组共用一套新训练的匹配 B0。无需为 A 和 C 分别训练两套对照。这样可统一初始化、随机流管理和训练协议，尤其适合核验目前仅千分之几至百分之几 dB 的小变化。如果未来专门恢复并验证旧的完整协议，可以再评估直接复用旧 B0 的条件；不能仅因网络结构兼容，就把历史检查点当作已验证的严格配对轨迹。

**建议的最小后续矩阵**

先完成三组各一个预先固定种子的完整训练，观察完整训练下的效应与学习曲线，再决定哪些候选值得补充独立种子。这个首轮只能作为可行性检查。建议种子顺序预先固定为 0、1、2，保留全部已完成结果，不能事后挑选种子。

| 组别 | 唯一方法差异 | 首轮完整训练 | 有前景后的扩展 |
|---|---|---|---|
| 匹配 B0 | 原始独立 PFA＋L1 | seed 0，300k | 增加 seed 1、2，作为共同对照 |
| A/B1 | 深层相关 PFA＋L1 | seed 0，300k | 若值得继续，增加 seed 1、2 |
| C/B3 | 原始独立 PFA＋结构损失 | seed 0，300k | 若值得继续，增加 seed 1、2 |

同一个种子的三组应共享解码器初始参数、数据顺序、输入噪声、Mixup 和共有的 PFA 随机分量；训练数据、batch、精度、优化器、学习率调度和预算保持一致。A 的相关性和 C 的损失权重在正式比较前固定。扩展时保持同一完整协议，不把首轮之后更改的超参数混入同一结果表。

“有前景”的判断规则应在首轮完整训练前写明，结合预设 OOD 增益、ID 退化限制、逐条件结果和训练稳定性，并明确用于判断的数据。单种子筛选通过也不构成有效性证明。若只有一个候选进入扩展，补齐该候选与匹配 B0 的种子，同时完整披露另一候选的首轮负结果；若两个候选都进入扩展，最终矩阵为三组各三个种子，共九次完整训练。三个种子仍然是有限重复，应报告各种子的配对差值及其离散程度，不能把大量图像或噪声实例当作大量独立训练重复。

当前没有必要预先增加 A+C 联合方案。只有在需要判断两项设计是否有相互作用时，再单独规划联合组及对应比较。

**评测边界、资源和状态**

CBSD68 的 48 张确认图和 Kodak24 在本轮没有用于 5k 开发筛选，但它们已在前一轮研究中被评测过。因此只能称为“本轮保留集”，不能称为整个研究从未接触过的测试集。如果后续方法或超参数依据这些结果继续调整，应记录其开发用途，并为最终独立泛化结论安排此前未用于方法选择的外部测试。

按当前两张 RTX 3090 的资源情况，首轮 **B0/A/C 各一个种子、各 300k 步，连同准备、检查和评测，暂以约 8–12 小时作为资源规划粗估**。这不是实测承诺，也不是九次完整训练的总预算。服务器存在其他作业，共享负载、可用显存、磁盘空间和评测排队都会影响完成时间；真正启动前应根据当时可用资源及短测速重新估算。不同共享负载下的墙钟耗时也不宜直接用于声称某个方法计算效率更高。

本文仅形成方法学建议。本轮已安排的 20k 确认继续按既定协议执行；新的 300k 完整训练尚未启动，其代码入口、配置、种子及评测规则仍需另行冻结和核验。
